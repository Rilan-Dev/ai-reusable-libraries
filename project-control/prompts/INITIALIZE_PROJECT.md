# APCP — Initialize Project

You are initializing an APCP-managed project.

1. Read repository-local instructions, inspect Git, source, tests, package/build/deployment configuration and existing docs.
2. Use Superpowers brainstorming. Treat a new project or architectural subsystem as architectural work.
3. Establish intent, users, constraints, success criteria, non-goals, architecture boundaries, security/tenancy, deployment and verification strategy.
4. Do not implement future product work during initialization unless explicitly authorized.
5. Create docs/project-control from the templates.
6. Create a phased implementation plan. Every phase has objective, scope, non-goals, dependencies, acceptance criteria, required evidence, authorization and entry/exit conditions.
7. Put unresolved choices in DECISIONS, defects in ISSUES, and uncertainty/impact exposure in RISKS.
8. Set exactly one primary NEXT_ACTION.
9. Record initialization in WORKLOG and make CHAT_CONTINUITY sufficient for a fresh chat.
10. Stop at the authorization boundary.

Initialization is complete only when a new AI can determine what is being built, the current phase, authorized scope, implementation state, verification state, open issues/risks and exact next action from repository state.
